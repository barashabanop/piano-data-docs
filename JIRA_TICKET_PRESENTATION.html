The Problem in Plain Language

On March 15, Cosmopolitan had 38 conversions. Piano stores each one as an individual event — who converted, when, on what page, from which device, and how much they paid.

Our pipeline doesn't get those individual events. Instead, we receive 9 separate summary files, each showing the same 38 conversions grouped by a single dimension — one file by device, another by location, another by page, and so on. None of these files tell us which users, which pages, or when each conversion happened. And they can't be combined because they share no common key.

This is not a bug in our pipeline — it is how Piano's export endpoint is designed. But there is a better endpoint available that gives us the individual events.

What We Get vs What Piano Has

Current Export Endpoint

9 separate CSV files, each showing conversions grouped by one dimension only:

  • Device CSV: "17 on mobile/android/chrome"
  • Location CSV: "5 from North Holland"
  • Page CSV: "3 from article X"

These files cannot be combined. There is no shared key between them.

Available Event-Level API

38 individual records, each carrying all information on one row:

  • User: "kelly@email.com"
  • Time: "March 15, 23:21:46 UTC"
  • Term: "Maak een account aan"
  • Unique ID: "TC0HTQMCP6LD"

Each record is a complete event with all dimensions together.

Both sources report 38 conversions for March 15 (Cosmopolitan). The totals are correct — the difference is in the structure.

What We Can't Do Today

1

We can't combine dimensions

"How many Android users from the Netherlands converted?" — The device CSV says 17 on Android. The location CSV says 31 from Netherlands. But we can't tell how many of those 17 Android users are from the Netherlands. The files have no shared key.

2

We can't backfill date ranges

"Give me daily breakdowns for March 1–15" — If we request that range, Piano gives us one lump sum for all 15 days. There is no date column in the CSV. We can't split it back into daily values. We have to fetch one day at a time.

3

We can't remove duplicates

"The pipeline ran twice for the same date" — Since export rows have no unique identifier, we can't detect or remove duplicates. If the same data is loaded twice, it doubles in our database with no way to tell.
